# Release Artifact Naming Conventions

## Format Specification
All Windows distribution artifacts (installers and standalone bundles) generated by the packaging pipeline MUST adhere to the following naming convention to clearly delineate testing channels from production releases.

`APMultitool_Setup_v[MAJOR].[MINOR].[PATCH]-[CHANNEL][ITERATION].exe`

### Variables
- **MAJOR.MINOR.PATCH**: Standard Semantic Versioning (e.g., `1.0.0`).
- **CHANNEL**: The staging channel. Valid options:
  - `alpha`: Internal STAX fleet testing (likely unsigned, high churn).
  - `rc`: Release Candidate for external staging cohorts.
  - *(Empty)*: Stable production release.
- **ITERATION**: Incremental build number for the channel (e.g., `1`, `2`).

## Examples
- `APMultitool_Setup_v1.0.0-alpha1.exe`
- `APMultitool_Setup_v1.0.0-beta1.exe`
- `APMultitool_Setup_v1.0.0-rc2.exe`
- `APMultitool_Setup_v1.0.0.exe`

## Pipeline Enforcement
The `packaging/windows/build_installer.ps1` script should accept environment variables (e.g., `$env:APP_VERSION` and `$env:RELEASE_CHANNEL`) to dynamically populate the output installer name and inject these parameters into the Inno Setup compiler (`/dMyAppVersion=...`).

## Universality Note
This naming convention will map 1:1 to macOS and Linux distribution artifacts in the future:
- `APMultitool_v1.0.0-rc1.dmg`
- `APMultitool_v1.0.0-rc1.AppImage`
